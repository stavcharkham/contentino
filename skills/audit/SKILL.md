# Audit Content

Audit answers one question: does this text sound like Lemonade? It is for content that
already exists - published posts, live product copy, other companies' writing. It is not a
gate. Nothing gets published, blocked or regenerated. Drafts that Contentino generates never
go through audit; they go through `submit_draft`.

## What audit does not check

Audited content never had a brief, so the brief-tracing criteria (claim sourced, why now,
quote fidelity) do not apply, and a missing source does not fail compliance. Compliance is
still reported as a flag when the text guarantees an outcome, makes an unsupported claim
about how the company judges a customer, or contradicts known policy.

## Getting the content

- **Pasted text**: use it verbatim. Do not fix, trim or reformat it.
- **A URL**: fetch the page and extract the article or copy text, dropping navigation and
  boilerplate. Tell the user if the fetch fails; do not reconstruct the content from memory.
- **A screenshot**: extract every user-facing string exactly as shown - button labels,
  headers, body copy, error text. List the extracted strings back to the user above the
  result so they can spot a misread.

Pick the content type: `product-microcopy` for UI copy from screenshots or the product,
`external-comms` for posts, announcements and articles.

## Submitting

Use the `audit_content` MCP tool when the connector is available. Otherwise use the HTTP
endpoint with the shared password, as described in the `contentino` skill:

```bash
curl -sf -X POST https://contentino-seven.vercel.app/api/contentino \
  -H "Authorization: Bearer <password>" -H "Content-Type: application/json" \
  -d '{"action":"audit","content_type":"<type>","body":"<the content, verbatim>","source":"<where it came from>","triggered_by":"<user name>"}'
```

`source` names where the content came from: "lemonade.com blog", "app screenshot",
"competitor site". It shows up in the ledger and on the dashboard.

Never score by hand. If the gate is unreachable, say so and stop.

## Reporting the result

Report what the gate returned, plainly:

- The score and one line saying what it means, e.g. "8.75 - reads like Lemonade" or
  "4.2 - off-brand". Do not soften a low score or dress up a high one.
- Each criterion with its score and the gate's reason, as returned.
- The compliance flag only if it failed, with the reason.
- Note that this was an audit: voice only, brief-tracing checks not applied.

No verdict paragraphs, no "overall this demonstrates". The numbers and reasons are the
report.
